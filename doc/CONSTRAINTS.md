# 项目约束(CONSTRAINTS)
- 禁止实现或引入用户注册、登录或云端账户。[§2.2]
- 禁止实现或引入云同步、服务端数据库或 HTTP API。[§2.2]
- 禁止实现在线修改原始简历排版或简历模板套用。[§2.2]
- 禁止生成排版完成的 PDF/DOCX 简历。[§2.2]
- 禁止实现或引入 OCR。[§2.2]
- 禁止自动抓取招聘网站 JD 或自动代替用户投递职位。[§2.2]
- 禁止按 `jobType` 拆分为多套产品或流程；`jobType` 仅可用于筛选、统计和后续规则扩展。[§3]
- 必须使用浏览器 IndexedDB 默认保存结构化数据、提取文本、分析结果、AI 对话和原始 PDF/DOCX，禁止更换为服务端或云端存储。[§1][§6.1]
- 必须使用 `localStorage` 仅保存少量界面设置和迁移标记，禁止在其中保存原始文件。[§6.1]
- 本地匹配必须完全在浏览器执行，禁止引入会为匹配过程发出网络请求的实现或依赖。[§2.1][§6.5]
- AI 外部接口必须兼容 OpenAI API，禁止更换为不兼容的专用接口。[§2.1][§6.6]
- 备份加密必须使用 Web Crypto API、PBKDF2 派生密钥和 AES-256-GCM，禁止更换加密方案或降低密钥强度。[§2.1][§6.7]
- 日历导出必须使用标准 `.ics` 格式，禁止使用专有日历文件替代。[§2.1][§6.4]
- `Resume.status` 只允许 `ready|extraction-failed|needs-review|deleted`，禁止写入其他状态值。[§5]
- `Interview.status` 只允许 `scheduled|completed|cancelled|rescheduled`，禁止写入其他状态值。[§5]
- 申请结果语义必须由稳定的 `Stage.kind` 区分普通、Offer、拒绝和放弃；阶段改名后禁止改变其结果统计语义。[§5][§6.3]
- AI 请求必须经用户预览并明确确认后发送，禁止自动发送或绕过确认。[§3][§6.6]
- 用户取消 AI 发送预览时必须保持未发送状态，禁止产生任何外发请求。[§3][§6.6][§8]
- AI 配置错误、API 地址非法、缺少 Key、连通性失败或请求失败时禁止外发，并必须保留本地资料和已保存对话。[§3][§6.6]
- 备份导入必须经过文件选择、密码输入、解密校验、版本与数据概览展示、相同 ID 检测、逐项冲突选择、预览和一次性提交，禁止跳过任一步骤直接覆盖数据。[§6.7]
- 备份冲突默认必须保留本地数据；使用备份覆盖或导入新副本必须经用户逐项选择，禁止自动覆盖。[§6.7]
- 错误密码、文件损坏、取消冲突处理或任一提交失败时，备份导入必须整体回滚，禁止部分生效。[§3][§6.7]
- 原始文件、确认后的提取文本、手动校正文本和 AI 建议必须分开保存，禁止相互覆盖。[§3]
- AI 建议禁止覆盖原始简历文件或自动生成 PDF/DOCX。[§6.6]
- AI 输出禁止虚构用户经历、技能、学历、成果或量化数据；不确定内容必须先询问用户。[§3][§6.6]
- 每个职位的 AI 对话必须隔离存储，禁止跨职位混用对话。[§6.6][§8]
- API 地址、模型名、API Key、组织 ID和自定义请求头必须仅存于本地设置，禁止写入业务记录或备份。[§5][§6.7]
- API Key、通知授权、临时 AI 上下文和发送预览永不允许进入备份。[§6.7]
- 日志和错误信息禁止包含简历内容、JD 内容、API Key 或面试私密笔记。[§3]
- 文件 hash 禁止与文件内容一起写入日志。[§6.2]
- 所有记录必须具有稳定 `id`、`createdAt` 和 `updatedAt`；更新记录时禁止更换稳定 ID。[§5][§6.1]
- 时间必须以绝对 ISO 时间保存，展示时必须使用记录自身时区或用户默认时区。[§5]
- `Interview.startsAt` 和 `Interview.timezone` 必须有效，禁止保存无效值。[§5]
- 简历上传只允许 PDF/DOCX，单文件不得超过 25 MB；不支持格式或超限文件必须拒绝。[§5][§6.2]
- 简历文本提取失败时必须保留原文件并进入手动粘贴或校正状态，禁止因提取失败删除原件或阻断其他功能。[§6.2]
- 删除简历原文件后必须保留 `ResumeUsageHistory` 中的名称和文本快照，禁止级联删除历史快照。[§5][§6.2]
- 每个职位只能有一个 `currentResumeId`；切换当前简历时必须追加使用历史和时间线事件，禁止覆盖旧记录。[§6.3]
- 招聘网址只允许保存为参考字段，禁止根据该网址抓取内容。[§5][§6.3]
- 阶段变化、简历切换、面试改期和备注必须保留时间线记录，禁止静默覆盖对应历史。[§3]
- 面试改期必须产生新的时间线记录，禁止仅覆盖原时间而不留痕。[§6.4]
- 浏览器通知被拒绝或浏览器关闭时，应用内提醒和 `.ics` 导出必须仍可用。[§6.4]
- `.ics` 必须包含标题、时间、时区、地点或链接、公司和职位。[§6.4]
- 本地 JD 匹配结果必须持久化为 `AnalysisResult`，并包含总体、必需和加分关键词覆盖率、已匹配项、弱匹配项、缺失项、证据片段和待人工确认项。[§6.5]
- 本地匹配结果只允许表达文本证据，禁止据此断言用户真实具备相应能力。[§6.5]
- 每次 AI 发送前必须展示当前简历版本、简历文本长度、JD 长度、消息数和目标 API 地址。[§6.6]
- 轻量备份禁止包含原始文件，只允许包含结构化数据、确认后的简历/JD 文本、匹配结果、AI 对话、申请时间线、面试和复盘。[§6.7]
- 完整备份必须在轻量备份内容基础上包含 PDF/DOCX 二进制。[§6.7]
- 每次备份导出必须生成新的随机 salt 和 IV，禁止复用；备份密码禁止保存。[§6.7]
- 删除职位、删除简历或清除全部本地数据必须二次确认，禁止一次操作直接删除。[§6.2][§7]
- 清除全部数据前必须展示数据数量，并要求输入确认词或再次确认。[§6.1][§7]
- 无网络时必须仍可完成简历管理、职位管理、面试记录和本地匹配，禁止将这些核心流程依赖于联网服务。[§2.1][§3][§7]
- 主要操作必须支持键盘操作、可见焦点、语义化标签和屏幕阅读器状态。[§6.8]
- 长文本、文件名、公司名和职位名在窄屏必须换行或截断，禁止遮挡操作控件。[§6.8]
- 错误、保存状态、通知授权和 AI 外发状态必须以可感知的状态提示呈现，禁止仅通过不可感知方式反馈。[§6.8]
- 格式不支持、大小超限、提取失败、重复文件、通知拒绝、AI 配置或网络错误、备份解密错误和冲突取消必须提供明确且可恢复的反馈。[§7]
- 简历和 JD 核心流程、数据模型、解析、匹配、时区、提醒、加密和冲突导入必须有自动化测试覆盖。[§8]
- 桌面端和移动端主要流程必须有端到端测试覆盖。[§8]
- 本地匹配测试必须断言未发出网络请求。[§8]
- AI 测试必须断言取消发送预览时不发送请求、对话按职位隔离且原始简历不被覆盖。[§8]
- 生产构建禁止包含测试文件、原始依赖目录或 API Key。[§8]
- README 必须说明安装、启动、离线使用、备份、恢复、通知、AI 配置和清除数据。[§8]
