# 求职工作台

一个无需注册、登录或服务端的本地优先求职管理 Web 应用。本仓库当前已完成
TypeScript 离线前端、生产构建和浏览器 IndexedDB 数据层；简历、职位、
面试、匹配、可选 AI 顾问和加密备份均在同一浏览器内协作。

## 功能页面

顶层导航收敛为 **5 个主区**，围绕"求职核心闭环（简历 → 投某职位 → 面这个职位
→ 复盘这个职位）"组织：

- **首页**：职位、简历、近期面试和待处理事项的聚合概览。
- **职位申请**：看板/列表视图、阶段管理，以及创建/编辑职位。看板支持**拖拽换列**
  改阶段（并保留键盘可达的"移动到…"下拉作无障碍兜底）。
- **简历库**：上传 PDF/DOCX、确认提取文本、编辑版本信息、导出和删除。
- **面试日历**：日/周/月视图。月视图为真正的 **6×7 日历网格**，格内标记当天面试
  数，点击某格展开当天面试详情；支持创建、编辑、改期、取消、完成和 ICS 导出。
  时区通过下拉选择器（`Intl.supportedValuesOf`，默认本地时区）选择。
- **设置与备份**：默认时区和提醒、AI 接口配置、数据清理以及加密备份恢复。

### 职位详情枢纽页

点击任一职位卡进入**职位详情枢纽页**，内部用二级子标签聚合该职位的一切：
概览、JD、简历（当前 + 历史）、匹配、AI 顾问、本职位面试、复盘、时间线、备注。
"JD 匹配"和"AI 顾问"是针对具体职位的动作，因此作为详情页子标签存在，无需在
顶层反复重选同一职位。

页面通过 URL hash 路由：顶层如 `#applications`、`#interviews`；职位详情为多段
`#applications/:id/:tab`（例如 `#applications/abc/matching`）。刷新后保留当前
位置，浏览器前进/后退可用。

## 技术栈

- **前端**：TypeScript + 原生 DOM（无框架），组件为 `create*(documentRef, options)`
  工厂函数；轻量事件总线 + hash 路由。
- **构建/测试**：Vite、Vitest（`jsdom` + `fake-indexeddb`）、Playwright（e2e，桌面 +
  移动视口）。
- **存储/加密**：浏览器 IndexedDB；Web Crypto API（PBKDF2 + AES-256-GCM）加密备份。
- **文档解析**：`pdfjs-dist`（PDF）、`mammoth`（DOCX）；`fflate` 用于打包。
- **无服务端**：无账户、无云同步、无后端数据库；仅可选 AI 顾问在用户确认后向兼容
  接口发请求。

## Windows 一键启动（推荐给只想用的人）

下载或克隆本仓库后，**双击根目录的 `启动.bat`**。脚本会自动完成：

1. 检测 Node.js（不满足要求时用 `winget` 安装 LTS 版本）
2. 首次运行自动 `npm install`
3. 在固定端口启动本地服务（`http://localhost:5173/`）
4. 自动打开浏览器

保持那个命令行窗口开着即可使用；关闭窗口就停止服务。之后每次双击 `启动.bat`
都会跳过已完成的步骤，几秒内可用。安装 Node.js 后如果提示"当前窗口还没识别到
它"，关掉窗口重新双击一次即可——这是 Windows 环境变量的正常表现。

如果系统没有 `winget`（较老的 Windows 10），脚本会提示你到
<https://nodejs.org/> 手动安装 LTS 版本，安装时保持默认选项即可。

> 必须通过 `localhost` 访问，不要直接双击 `dist/index.html`。应用使用 ES
> modules、IndexedDB 和 Web Crypto，`file://` 协议下模块加载与加密备份都会失效。
> 同理，通过局域网 IP（`http://192.168.x.x`）访问也不是安全上下文，加密备份会不可用。

## 环境要求

- **Node.js 22.22.2 或更高版本**（已验证：22.23.2；Node 24.15+ / 26+ 同样可用）
- npm 10 或更高版本

版本下限由依赖决定，其中 `jsdom@30`（测试环境）要求
`^22.22.2 || ^24.15.0 || >=26`，是全部依赖里最严格的一项；`vite`/`rolldown`
要求 `^20.19 || >=22.12`。`package.json` 的 `engines` 字段已声明该下限。

## 安装与启动（命令行，跨平台）

```bash
npm install
npm run dev
```

开发服务器启动后，打开终端显示的本地地址。应用没有账户系统，不需要配置
服务端数据库或 HTTP API。Windows、macOS 和 Linux 上的全部 npm 脚本均可直接运行
（不依赖 `sh` 等 POSIX 工具）。

运行自动化测试：

```bash
npm test
npm run test:e2e
```

测试环境使用 `fake-indexeddb` 提供浏览器兼容的 IndexedDB 实例，不会连接外部
数据库。`npm run test:e2e` 会启动本地 Vite 服务，并使用 Playwright 覆盖桌面和移动
视口；如果系统禁止监听本地端口，需要允许该命令访问 `127.0.0.1`。

## 生产构建

```bash
npm run build
npm run check:production
npm run preview
```

`npm run build` 先执行 TypeScript 类型检查，再将生产静态资源写入 `dist/`。
`npm run check:production` 会重新构建并递归审计 `dist/`，拒绝测试/E2E 源码、
`node_modules` 或原始依赖目录，以及疑似硬编码 API Key 和敏感 AI 配置。审计失败
只输出文件路径和规则名，不输出文件正文或密钥内容。通过审计的 `dist/` 可以由普通
静态文件服务器托管，不需要应用服务端。

## 离线使用

依赖安装和首次取得静态资源后，可以断开外网并继续使用本地开发服务器、
`npm run preview` 或其他本地静态文件服务器打开应用。当前应用入口只加载构建
产生的 HTML、CSS 和 JavaScript；启动和离线核心流程不执行认证、远程数据库连接或
应用 HTTP 请求。只有用户确认 AI 发送后，才会按本地配置向目标兼容接口发出请求。

离线能力指应用和本地数据流程不依赖外网；浏览器仍需从本机或选定的静态文件
服务器加载 `dist/` 资源。本任务没有注册 Service Worker，因此不会将首次访问过
的远程站点自动缓存为可离线站点。

断网后仍可上传并管理 PDF/DOCX 简历、确认或手动校正提取文本、创建职位并粘贴
JD、绑定和切换当前简历、跟踪申请阶段、运行浏览器内本地匹配、安排或改期面试、
填写复盘，以及导出或恢复加密备份。仅可选的 AI 顾问请求需要网络。

## 本地存储边界

- IndexedDB 是业务结构化数据、提取文本、分析结果、AI 对话和原始 PDF/DOCX
  二进制文件的默认存储位置。
- `localStorage` 仅允许保存少量界面设置和迁移标记，禁止保存原始文件、Blob、
  简历文本、JD 文本或其他业务正文。
- API 地址、模型、API Key、组织 ID 和自定义请求头将通过独立的本地敏感设置
  接口管理，不得写入业务记录或备份。
- 浏览器数据属于当前浏览器配置文件。清理站点数据可能永久删除本地记录，重要
  资料应定期导出完整加密备份，并在清除前确认备份文件和密码均可用。

## 加密备份

应用的“加密备份与恢复”面板提供两种备份，两者都只在浏览器内读取 IndexedDB，
使用 Web Crypto API、PBKDF2 和 AES-256-GCM 加密后下载，不会发出网络请求：

- 轻量备份包含结构化业务数据、确认后的简历/JD 文本、匹配结果、AI 对话、申请
  时间线、面试和复盘，不包含上传的 PDF/DOCX 原始文件。
- 完整备份包含轻量备份的全部内容，并包含所有 PDF/DOCX 原始文件二进制。

每次导出都会生成新的随机 salt 和 IV。备份密码只存在于当前页面交互的内存中，
不会写入 `localStorage`、IndexedDB、业务记录或备份文件。应用无法找回或重置备份
密码；遗忘密码后无法解密对应文件，因此应在安全位置自行保管密码。

## 恢复备份

恢复必须依次完成：选择 `.json` 备份文件、输入密码、查看解密后的版本与数据概览、
逐项处理相同 ID、查看导入预览、最终确认。最终确认前不会写入 IndexedDB。冲突
默认选择“保留本地”；“使用备份覆盖”和“导入为新副本”必须由用户对每个冲突项
明确选择，重复导入同一文件也不会静默覆盖已有记录。

冲突较多时可用“全部保留本地 / 全部使用备份 / 全部导入副本”一键批量设置全部
冲突项，之后仍可逐项微调；批量按钮只是一次性设置各冲突项的选择，默认仍为
“保留本地”，覆盖本地数据始终需要显式选择并走完预览与最终确认。

密码错误、文件损坏、格式或版本校验失败，以及在任一步骤取消，都不会改变现有
资料。最终提交覆盖所有相关 store 的单个 IndexedDB 事务；任一写入失败会整体
回滚，不会留下部分导入结果。成功后数据写入当前浏览器配置文件，刷新页面后仍可
读取。恢复过程同样完全离线，不依赖服务器。

## 设置与清除本地数据

默认时区、提醒、界面偏好和迁移标记由 `src/settings/preferences.ts` 写入少量
`localStorage` 键。AI API 地址、模型、Key、组织 ID 和自定义请求头由
`src/settings/secrets.ts` 写入 IndexedDB 的独立敏感设置 store，不会出现在业务
仓储记录中。

`previewDataClear` 可读取结构化记录、文本记录和原始文件 Blob 的数量。调用
`clearAllData` 时必须传入 `confirmed: true` 或确认词 `DELETE`；取消不会改变任何
数据，确认后会清空 IndexedDB 全部业务 store、敏感设置和应用管理的界面偏好键。
其他应用写入的 localStorage 键不会被删除。清除过程
发生错误时会恢复清除前快照并返回 `{ cleared: false, error }`。

清除操作不可依赖应用内撤销。执行前应先查看界面展示的数据数量，导出并验证完整
备份，然后进行二次确认。清除站点数据或浏览器配置文件也可能绕过应用内确认并永久
删除资料；轻量备份不能用于恢复原始 PDF/DOCX。

## 通知与 AI 配置

面试提醒优先使用浏览器通知；用户拒绝授权时，应用内提醒仍可用。浏览器关闭后
无法执行后台通知，重新打开应用即可查看到期提醒。任何面试都可以导出标准 `.ics`
文件（包含标题、绝对时间与时区、地点或职位链接、公司和职位），交给系统日历
继续提醒；ICS 导出不依赖通知权限或网络。

AI 顾问使用 OpenAI Chat Completions 兼容接口。设置中填写 API 地址、模型名、API
Key，可选组织 ID 和自定义请求头；这些敏感设置只保存在本地，不进入职位记录或
备份。每次请求前都会展示当前简历版本、简历/JD 文本长度、消息数和目标地址，用户
明确确认后才发送。取消预览、配置无效、缺少 Key、连通性失败或请求失败都不会外发
资料，并保留本地对话以便修正配置后重试。AI 建议只作为独立结果保存，不覆盖原始
简历或自动生成 PDF/DOCX。

## 删除与隐私边界

应用没有账户、云同步、服务端数据库、招聘网站抓取或自动投递。清除全部本地数据
前必须先查看记录数量，并输入确认词 `DELETE`（或在界面完成第二次确认）；职位和
简历删除同样需要二次确认。确认后会清空当前浏览器的 IndexedDB、敏感设置及应用管理的偏好键，
不会删除其他应用写入的 `localStorage` 键，且不能撤销，因此应先验证完整加密备份。浏览器设置中直接清除站点数据也
可能绕过应用确认并永久删除资料。
